# PDF 逐页 OCR 转 Markdown

用户已确认目标是阅读顺序一致，不要求视觉版式复刻。沿用 DashScope 协议，模型、地址、密钥通过 .env 配置。联调后默认改用 qwen3-vl-plus 执行 OCR 和布局定位：原 qwen-vl-ocr-2025-11-20 在合成双栏插图页漏图或输出无效坐标；新模型在同样页面正确输出插图与阅读顺序。这是实现阶段基于实测做出的选择，成本和支持范围取决于对应模型。

方案：逐页渲染为 PNG，请模型返回严格 JSON 内容块数组（Markdown 文本或带 0–1000 坐标的图片），数组即阅读顺序。程序不按 y 坐标重排多栏内容；图片从同一渲染图裁剪，Base64 内嵌到对应块的位置。保存 output/<PDF stem>/<1-based page>/<page>.md，以及 page.png、layout.json 便于核对。

曾考虑 PDF 原生图片提取，但扫描件的插图无法这样定位；整页图片内嵌虽保持外观，不满足可用正文的目标。选用模型布局块与裁图方案。模型识别准确度及顺序不能绝对保证，需要真实样本核验。

支持页码范围；页失败记录到 manifest.json 并继续下一页，失败退出码非零；拒绝静默接受截断、无效坐标或无效 JSON。不覆盖已有输出目录，避免旧结果混入。空白页允许空 blocks。CLI 不打印密钥或原始响应。

不包含 Web/API 服务、RAG、合并 Markdown、像素布局复刻。当前目录未初始化 Git，不创建远端仓库。
